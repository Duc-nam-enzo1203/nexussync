# ADR 003: Safe Tombstone Garbage Collection & Snapshot Compaction

## Status
Accepted

## Context & Problem Statement
In Sequence CRDTs (such as RGA, YATA, or Automerge), deleting a character cannot immediately free its memory. If character $C$ is physically deleted from the array, a concurrent edit from an offline peer whose cursor was anchored to $C$ (`leftId = idOf(C)`) will fail to find its anchor upon reconnection, resulting in document divergence or corrupted text order.

Consequently, CRDTs retain deleted elements as **tombstones** (`deleted: true`). In long-running collaborative documents (e.g. drafting an essay, editing code), the accumulation of hundreds of thousands of tombstones degrades memory footprint and increases linear scanning latency.

## Decision Drivers
- **Safe Memory Reclaiming**: Tombstones must be safely purged without ever risking anchor reference errors from reconnecting peers.
- **Fast Startup & Rehydration**: Initializing a document must not require replaying millions of granular keystroke deltas from the beginning of time.
- **Deterministic Consensus on Stability**: All replicas must agree on when an operation has become **causally stable**.

## Considered Options
1. **Never Prune Tombstones**: Safe, but leads to memory exhaustion over time.
2. **Fixed-Time TTL Pruning**: Prunes tombstones older than 7 days. *Vulnerable*: If a peer was offline for 8 days and reconnects, divergence occurs.
3. **Causal Stability Consensus (Min-Acknowledged State Vector)**: A tombstone is pruned only when every known peer has explicitly acknowledged witnessing the sequence number.

## Decision
We implemented **Causal Stability Consensus** via the `SnapshotManager`:

### 1. Stability Condition
Let $SV_{\text{cluster}} = \{ SV_1, SV_2, \dots, SV_n \}$ be the set of state vectors acknowledged by all $n$ active cluster members.
The **Minimum Acknowledged Vector** is defined pointwise as:
$$SV_{\text{min}}[P] = \min_{i=1}^n (SV_i[P])$$

Any deletion tombstone generated by origin peer $P$ with sequence counter $seq$ is defined as **causally stable** if and only if:
$$seq \le SV_{\text{min}}[P]$$

### 2. Pruning Mechanism
When $seq \le SV_{\text{min}}[P]$, it is mathematically impossible for any active peer to ever produce a future edit anchored to that tombstone. The `SnapshotManager` permanently removes the node from the RGA linked array and rebuilds the index map.

### 3. Consolidated Snapshots
Periodically (every $K$ operations), a consolidated state snapshot is generated. New peers synchronizing for the first time receive the snapshot directly, followed only by subsequent uncompacted deltas.

## Consequences

### Positive
- Memory footprint is bounded and proportional to the **visible document size**, rather than total historical keystrokes.
- Linear iteration speed across the text array remains optimal.
- 100% mathematical guarantee against dangling anchor divergence.

### Negative / Trade-offs
- If a known peer remains offline indefinitely without disconnecting from the cluster membership list, $SV_{\text{min}}$ cannot advance, stalling garbage collection until the stale peer is evicted.
